# `scripts/tests/*.sh` stderr-discarded flake-hider audit — 2026-05

**Issue:** #4528 (parent: #4383)
**PR:** TBD
**Date:** 2026-05-08

## TL;DR

Issue #4528 calls for an audit of `scripts/tests/*.sh` for the canonical
#4383 anti-pattern: a shell test captures a command's stdout via
`$(... 2>/dev/null)`, captures the rc, and asserts on the rc — so when
the assertion fails (e.g. CI-only flake), the only signal is
`expected: X / actual: Y` with no stderr, no stdout dump, no
diagnostic context for the next agent.

This document is the audit; it lists every site in `scripts/tests/`
that fits the harm class and documents which were patched in this PR
versus left alone (with rationale).

The audit was generated by `tmp/audit_stderr_discarded.py` (kept in
this branch for reproducibility) walking every `*.sh` file under
`scripts/tests/`.

## Audit method

Counted as harmful when ALL three conditions hold:

1. A line of the form `VAR=$( ... 2>/dev/null ...)`
   (or `... > /dev/null 2>&1` / `&> /dev/null` — same effect: stderr
   is gone) — i.e. the captured command is allowed to fail silently.
2. Within 5 non-blank, non-comment lines below, an exit-status
   capture: either `RCVAR=$?` on a separate line, or
   `... || RCVAR=$?` inline on the same line as the capture.
3. Within 60 non-blank lines after the rc capture, an `assert_*`
   call referencing `$RCVAR` — i.e. the captured rc is asserted on.

The third condition is load-bearing. If the rc is captured but only
checked by a hand-rolled `if [[ $rc -ne 0 ]]; then fail "..." "context"`,
the `fail` message can carry whatever diagnostic context the test
author chose — usually `output` plus the rc, so the failure is
self-explanatory. The flake-hider class is the silent `assert_*` form,
where on rc mismatch the harness prints only `expected/actual`.

The audit deliberately does NOT flag the much wider class of
`$(cmd 2>/dev/null)` captures used for stdout-only inspection (where
the rc is implicitly ignored). Those are intentional — the test's
intent is "I only care about stdout" — and rewriting them all would
churn the codebase without addressing the actual flake-hider harm.

Both sites are in `test_profile_shell_test.sh` and both invoke the

pre-patch file, inside the entrypoint test block); these two

### Adjacent harmful site: #4383-class without an rc capture

`scripts/tests/test_profile_shell_test.sh:230` — Test 8:

```bash
out6=$("$PROFILER" --tsv "$TMPDIR_TEST/top1.tsv" --top 1 "$fixture1" 2>/dev/null)
top_rows=$(printf '%s' "$out6" | awk '/^Top 1 longest sections:/{flag=1; next} /^----- end -----/{flag=0} flag' | wc -l | tr -d ' ')
assert_eq "--top 1 prints 1 row" "$top_rows" "1"
```

Test 8 doesn't capture rc at all — it computes `top_rows` from `out6`'s
stdout and asserts on that. But the failure mode is morally identical
to the #4383 shape: if the profiler dies silently, `out6` is empty,
`top_rows` is 0, and the assertion fires with `expected: 1 / actual: 0`
and no other context. The harm class is "rc + or stdout-derived
metric — assertion fires, stderr is gone, agent has no signal." This
site was patched in this PR alongside the two strict matches above.

### Sites considered and intentionally NOT patched

These are stderr-discarded captures that the audit found, but where
the test's existing failure path already includes diagnostic context.

#### Tests that include stdout in their `fail` message

These are the common case across the codebase. The failure path is:

```bash
output=$("$WRAPPER" 1 2>/dev/null) || exit_code=$?
if [[ "$exit_code" -eq 1 && "$output" == *"expected"* ]]; then
    pass "..."
else
    fail "..." "exit=$exit_code output='$output'"
fi
```

When the assertion fails, the operator sees both the rc and the
captured stdout. Stderr is still gone, but the residual diagnostic
quality is high enough that an unexplained rc shift would be
distinguishable from "the wrapper printed the wrong stdout."

Examples (~60+ sites in this class — listed once per file):

* `scripts/tests/test_check_issue_plan_blocked.sh` (lines 107, 118, 129, 146, 159, 172, 183) — every test calls `fail` with `exit=$exit_code output='$output'`.
* `scripts/tests/test_check_duplicate_pr.sh` (lines 93, 128, 144) — same pattern.
* `scripts/tests/test_check_shipped_pr.sh` (~25 lines: 143, 192, 239, 280, 382, 465, 539, 583, 624, 666, 711, 761, 805, 847, 906, …) — same pattern.
* `scripts/tests/test_dev_db_query.sh:474` — `fail` includes `rc=$rc stdout='$stdout'`.
* `scripts/tests/test_run_py.sh:409` — `fail` includes `exit code: $exit_code, output: $output`.
* `scripts/tests/test_gh_comment_with_retry.sh:224` — `fail` includes the captured `help_output`.
* `scripts/tests/test_adopt_pr.sh:190` — uses captured `adopted_branch` in the comparison; failure path inspects branch state.
* `scripts/tests/test_gemini_review.sh:379` — `fail` includes `exit_code` plus the recorded mock invocations.

Patching these to also capture stderr would be ~60+ lines of
repetitive churn for marginal benefit. Most of the harmful
information that would surface in stderr (e.g. an unexpected fatal
inside the wrapper) would also be visible in stdout, since the
wrappers use `gh-comment-with-retry.sh`-style structured stderr +
mirror-to-stdout patterns.

If a flake materialises in any of these tests in the wild and the
existing diagnostic context is insufficient, that specific test can
be hardened in a follow-up using the `*.err`-capture-and-dump pattern
documented below.

## The pattern this PR uses to patch (recipe)

For each harmful site, the fix is:

```bash
# Before:
out1=$("$PROFILER" --tsv "$tsv1" --top 5 "$fixture1" 2>/dev/null)
exit1=$?
assert_eq "basic fixture exits 0" "$exit1" "0"

# After:
err1="$TMPDIR_TEST/fixture1.err"
out1=$("$PROFILER" --tsv "$tsv1" --top 5 "$fixture1" 2>"$err1")
exit1=$?
assert_eq "basic fixture exits 0" "$exit1" "0"
if [[ "$exit1" != "0" ]]; then
    echo "  ── #4528 stderr dump (basic fixture) ──"
    tail -n 50 "$err1" 2>/dev/null | sed 's/^/    /'
    echo "  ── end #4528 dump ──"
fi
```

This mirrors PR #4526's pattern exactly (see
`docs/investigations/profile-shell-test-rc2-flake-2026-05.md`). The
existing assertion fires first; the dump runs only if the assertion
failed (i.e. `exit1 != 0`).

## Why not patch every `2>/dev/null` site

Three reasons:

1. **Signal-to-noise cost.** Roughly 393 lines under `scripts/tests/`
   contain `2>/dev/null`. Most are intentional stderr silencing in
   cleanup paths, mocks, or fail-message formatting. Replacing them
   wholesale would add ~393 stderr-capture files and ~393 conditional
   dump blocks, mostly for code paths that never fire the assertion.
2. **Patching the wrong layer.** The wider concern is "the harness
   doesn't provide diagnostic context on assertion failure." A
   structural fix lives in the assert helpers — `assert_eq` /
   `assert_ge` could optionally accept a context-callback or a
   "here's the most recent stderr file to dump on failure" hook. That
   is a follow-up, not in this PR's scope; see the recommended
   follow-up below.
3. **Signal of recurring harm.** Of the wide set of `2>/dev/null`
   sites, only the #4383 / #4528 pair has actually surfaced as a
   flake-debugging blocker. The right time to extend this to other
   sites is when (and if) one of them flakes — at which point the
   recipe above is mechanical to apply.

## Recommended follow-up

* File a `type/dx` issue: extend `scripts/tests/_test-helpers.sh`
  (the shared assert harness, if one exists; if not, build one) so
  every `assert_*` call optionally accepts a `--err-file FILE` flag
  whose contents are dumped on assertion mismatch. With that helper
  in place, the canonical recipe collapses from 6 lines to 1 line per
  site, and the cost / benefit math for patching the long tail of
  ~60+ silent assert sites flips from "not worth it" to "trivially
  worth it."

## Update — 2026-05-08: helper-driven 1-line recipe is now available (#4540)

The recommended follow-up landed as `scripts/tests/_test-helpers.sh`
in PR for #4540. The helper provides `pass`, `fail`, `assert_eq`,
`assert_ge`, `assert_contains` with optional `--err-file FILE`
support — on assertion mismatch, the helper dumps FILE's last 50
lines bracketed with the `── #4540 stderr dump ──` banner. Pass-path
calls are silent on `--err-file`, mirroring the dump-on-mismatch
contract this audit established.

### The new 1-line recipe

```bash
# Source the shared harness once at the top of the test:
. "$SCRIPT_DIR/tests/_test-helpers.sh"

# Then at each site, the canonical 6-line block:
err1="$TMPDIR_TEST/cmd.err"
out1=$("$WRAPPER" 1 2>"$err1") || exit_code=$?
assert_eq "exit code matches" "$exit_code" "1"
if [[ "$exit_code" != "1" ]]; then
    echo "  ── #4528 stderr dump ──"
    tail -n 50 "$err1" 2>/dev/null | sed 's/^/    /'
    echo "  ── end #4528 dump ──"
fi

# ... collapses to 4 lines (or 3 with the existing rc capture):
err1="$TMPDIR_TEST/cmd.err"
out1=$("$WRAPPER" 1 2>"$err1") || exit_code=$?
assert_eq "exit code matches" "$exit_code" "1" --err-file "$err1"
```

The conditional dump block disappears entirely; the helper handles
it.

### Worked example migrations from this audit's harm class

The three patched sites in `scripts/tests/test_profile_shell_test.sh`
were all migrated to the helper-driven form as part of #4540.
Compare before-and-after:

**Site 1 — fixture1 (basic fixture):**

```bash
# Before (#4528 inline form):
err1="$TMPDIR_TEST/fixture1.err"
out1=$("$PROFILER" --tsv "$tsv1" --top 5 "$fixture1" 2>"$err1")
exit1=$?
assert_eq "basic fixture exits 0" "$exit1" "0"
if [[ "$exit1" != "0" ]]; then
    echo "  ── #4528 stderr dump (basic fixture) ──"
    echo "  profiler stderr (last 50 lines):"
    tail -n 50 "$err1" 2>/dev/null | sed 's/^/    /'
    echo "  fixture stdout (last 50 lines):"
    printf '%s\n' "$out1" | tail -n 50 | sed 's/^/    /'
    echo "  ── end #4528 dump ──"
fi

# After (#4540 helper-driven form):
err1="$TMPDIR_TEST/fixture1.err"
out1=$("$PROFILER" --tsv "$tsv1" --top 5 "$fixture1" 2>"$err1")
exit1=$?
assert_eq "basic fixture exits 0" "$exit1" "0" --err-file "$err1"
```

**Site 2 — fixture5 (no-section fixture):** Same shape — the
6-line conditional dump block is replaced by a single `--err-file`
argument on the `assert_eq` call.

**Site 3 — Test 8 (--top 1 stdout-derived metric):** Same shape, but
the assertion is on a derived metric (`top_rows`) rather than the rc
directly. The helper's `--err-file` still surfaces the profiler's
stderr on mismatch — matching the harm class this audit identified.

### Cost/benefit math now flips for the long tail

The audit's "Sites considered and intentionally NOT patched" section
(~60+ already-debuggable sites whose `fail` messages already include
`output`) argued patching each was high-churn for marginal benefit
under the inline 6-line recipe. With the helper-driven 1-line form,
each site is one extra arg on the existing `assert_*` call (or one
`fail "..." "$(tail -n 50 "$err_file")"` for the hand-rolled `fail`
sites). A follow-up `type/dx` issue can audit those sites for
opportunistic migration as they're touched for other reasons; a
wholesale sweep is still not worth it (the `fail` message + stdout
remain a sufficient signal in most cases), but the upgrade is now
mechanical.
