# /dispatcher-daily-report skill

Generate the daily dispatcher health report, commit it to a branch, and open an auto-merge PR. This skill is non-interactive — it runs queries, renders markdown, and ships a PR without LLM review of the content.

**Trigger:** The dispatcher daemon fires this skill daily at 12:00 UTC via the `dispatcher-daily-report` row in `dispatcher.scheduled_skills`.

Do not ask for confirmation. Work autonomously through every step.

---

## Step 0 — Setup

Establish the report date (UTC) and output path. The worktree root is the repo root.

Retrieve today's UTC date:

```
date -u +%F
```

Store the result (e.g. `2026-04-25`) as the report date. All subsequent steps reference this value.

Confirm the output directory exists:

```
ls docs/dispatcher-daily/
```

The directory is committed with a `.gitkeep` file. No mkdir needed.

---

## Step 1 — Generate the report

Run the daily_report script, writing output to the dated path:

```
python scripts/dispatcher/daily_report.py --output docs/dispatcher-daily/REPORT_DATE.md
```

Replace `REPORT_DATE` with the literal date string retrieved in Step 0 (e.g. `2026-04-25`).

The script reads `DATABASE_URL` from the environment (injected by the ECS task definition) and runs five SQL queries against the last-24h window. On success it writes the markdown file and exits 0. On any DB error it exits non-zero — let the failure propagate so the scheduler records the run as failed.

---

## Step 2 — Create a branch and commit

Check out a new branch for this report. Use the literal date string from Step 0:

```
git checkout -b dispatcher/daily-report-REPORT_DATE
```

Stage the generated report file:

```
git add docs/dispatcher-daily/REPORT_DATE.md
```

Write the commit message to a temp file. Use the Write tool with content that includes the literal date (no shell substitution):

File path: `{worktree}/tmp/daily-report-commit-msg.txt`

Example content (substitute actual date):

```
chore(dispatcher): daily report REPORT_DATE

Auto-generated dispatcher health report for REPORT_DATE.
Covers last-24h throughput, failure breakdown, diagnoser
activity, stuck issues, and Phase-4 health.

Generated by /dispatcher-daily-report skill (issue #3375).
```

Commit using the file:

```
git commit -F {worktree}/tmp/daily-report-commit-msg.txt
```

---

## Step 3 — Push

Push the branch to origin:

```
git push -u origin dispatcher/daily-report-REPORT_DATE
```

---

## Step 4 — Open a PR

Write the PR body to a temp file using the Write tool.

File path: `{worktree}/tmp/daily-report-pr-body.txt`

Example content (substitute actual date):

```
## Daily dispatcher health report — REPORT_DATE

Auto-generated by the `/dispatcher-daily-report` scheduled skill (issue #3375).
Covers the last 24 hours of dispatcher operation.

### Contents
- Throughput summary (agents started, terminated, green streak)
- Top-3 failure categories (bold callout)
- Full failure breakdown by phase x category
- Diagnoser activity (recommendations vs outcomes)
- Stuck issues (3+ same-category failures per issue in window)
- Phase-4 health (daemon restart count)

*CloudWatch metrics (tick_elapsed_s p50/p95, scheduler_tick_stalled) are placeholders pending the follow-up in #3375.*
```

Create the PR:

```
gh pr create \
    --repo judgemind/judgemind \
    --title "chore(dispatcher): daily report REPORT_DATE" \
    --body-file {worktree}/tmp/daily-report-pr-body.txt \
    --base main
```

Record the PR number from the output (e.g. `#1234`).

---

## Step 5 — Auto-merge

Enable auto-merge so the PR merges as soon as CI passes:

```
gh pr merge PR_NUMBER \
    --repo judgemind/judgemind \
    --auto \
    --squash \
    --delete-branch
```

Replace `PR_NUMBER` with the number captured from Step 4.

---

## Step 6 — Return verdict

The skill is complete. Output the following verdict string so the dispatcher's `handle_scheduled_skill` function records success:

```
SHIPPED
```

---

## Guardrails

- **No `$()` in shell commands.** Retrieve dynamic values (date, PR number) as separate tool calls and substitute manually.
- **No heredocs, no quoted strings with `&&` or `;`.** Use Write tool for multi-line content.
- **All temp files go in `{worktree}/tmp/`.** Never `/tmp/`.
- **If daily_report.py exits non-zero, do not proceed to Steps 2-5.** Let the scheduler record the failure and retry.
- **Do not edit the report content.** The Python script is authoritative; this skill is a delivery wrapper only.
